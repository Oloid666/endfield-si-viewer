# Endfield Si 3D Viewer

以 iPhone Safari 為優先的 Three.js 人物展示頁。已接入使用者從 Sketchfab 下載並提供的祀 GLB，附有模型來源與 CC BY 4.0 署名；詳見 `public/models/SOURCE.md`。無後端、資料庫或付費 API。

## 三個區域與遊戲原型

上方切換 **小蔥區（祀）／大蔥區（莊方宜）／遊戲區**。同一時間只保留一個人物場景，切換才載入另一個模型；兩份模型各自無損壓縮、驗證與快取，不會互相刪除。網址 `#si`、`#zhuang`、`#hub`、`#game`、`#escape`、`#raft`、`#ride` 可直接進入，重新整理仍保留區域。

- **小蔥區**：保留表情、眼神、三段短劇及鏡頭功能；切換不同表情時滑桿歸零並清除舊台詞。對話全面重整仍列待辦，這版未改寫原有四區文案。
- **大蔥區**：使用使用者提供的原始莊方宜 GLB。複用全身、靠近點、轉背、鞋靴三段環繞與第四段恢復。頭部／腳部取景使用此模型的實際骨骼錨點；目前為靜態展示，未把祀的表情與動作硬套到另一套骨架。來源及 SHA-256 見 `public/models/ZHUANG-SOURCE.md`。
- **遊戲區**：「危機合約：禁止停手」原型，約 30 秒、112 BPM、48 個左右音符，四拍預備後開始。箭頭到判定線時按左／右甩，桌面可用 F／J 或左右方向鍵。自製合成器節拍，第一次按開始才啟動音訊，無外部歌曲。

遊戲有 Perfect／Good／Miss、分數、連擊、評級及重玩；中場蔥接管、反甩祀，按鍵規則保持一致。暫停、切到背景與離開區域會停止節拍；回來需按繼續。手機使用大按鈕，遊戲期間暫停 OrbitControls，避免操作互相干擾。音訊不可用時仍可玩視覺節奏。

`RhythmEngine` 是獨立的絕對時鐘判定器；`RhythmGame` 管 UI、原生 Web Audio 與既有 render loop 的更新；`GameStage` 重用祀的舞步和實際手腕抓握。沒有額外 Renderer、RAF、物理引擎、排行榜服務或遊戲框架。

## 迷你帝江號／辦公椅－試作

[祀坐迷你帝江號](https://oloid666.github.io/endfield-si-viewer/?rider=si#ride)／[莊芳宜坐辦公椅](https://oloid666.github.io/endfield-si-viewer/?rider=zhuang#ride)，或遊戲區 → **迷你帝江號／辦公椅－試作**。與竹筏是獨立入口；開始／暫停面板可切換兩種坐騎，換角色會重新開局。

- 祀坐在懸浮迷你艦的座椅上，拖著黑白小聰明；莊芳宜坐帶輪辦公椅，由龍泡泡先拉出門，再主客對調。小聰明補上圓頭、紙面與綠色筆觸；龍泡泡補上半瞇漸層眼、金角、紅繩；迷你艦增加環架、桁架、艙段、核心與 O.M.V. 標記。這些均為程序二創簡模，參考來源見 [美術紀錄](docs/RIDE-ART-REFERENCES.md)，沒有放入官方模型或參考圖。兩套人物仍使用原始 GLB；接受衣物穿模。
- 道路由 280 公尺／12.6 公尺寬擴至 **900 公尺／21 公尺寬**，包含清波寨快速路、連彎工業區、禁止正常上班三段。祀線巡航由約 42 增至 **68 km/h**，甩尾／息壤噴射可破百，上限約 122 km/h；莊線依下方劇情變速。這些是遊戲內數值。一般轉向較跟手，彎道有向外慣性，按煞車時保留更多側滑，需要適度反打。
- **方向＋煞車** 蓄甩尾Ⅰ／Ⅱ／Ⅲ，拖痕與量表分別顯示青、橘、紫色，放開煞車依蓄力程度噴射並取得甩尾分數。桌面用方向鍵／A、D，空白鍵煞車。大甩尾／碰撞會轉椅、拉近鏡頭並出現吐槽。
- **氣態息壤噴射**：開局一罐、最多兩罐，路上可拾取；按右下道具或 E 噴射約 3.2 秒。噴焰、煙霧、畫面邊緣風線與速度回饋配合顯示，期間不能連按浪費另一罐。碰撞會取消噴射、減速、反彈並短暫停止物理位移，附星星、煙塵、壓扁跟班與鏡頭震動，之後可繼續行駛。
- 結算顯示用時、最高速度、甩尾分數／次數、墨印、碰撞及息壤用量。保留暫停、重來、到站重玩，離開恢復角色、相機 FOV 與背景。`?rider=zhuang#ride` 可直接開莊芳宜版本，重新整理保留角色。
- **莊芳宜劇情線「本來只想讓她下班」**：獨立 2600 公尺、通常約 80～90 秒。前 22 秒由玩家操控龍泡泡拉椅子兜風（約 50 km/h）；直線公告「冠軍獎品由管理員贊助」，第 25～27 秒交換前後位置，莊接管後約 130 km/h；最後嫌太慢，辦公椅升空至 6 公尺、約 210 km/h，法術上限約 252 km/h。這些是遊戲內數值，不是效能量測。已移除舊的自動息壤橋；飛行仍接受左右控制。
- **莊線操作與畫面**：三顆大按區 `◀／▶／✦`，按住轉向、持續約 0.35 秒進入甩尾，回正可觸發出彎加速；不另放煞車按鈕。第 27 秒解鎖法術／E，最多存兩次，拾取息壤補充。前六秒顯示操作引導，之後按區變淡、按下亮起。行駛時收起頂端分區導覽及大標題，僅留小型狀態列與單句短字幕；暫停後恢復選單。公告安排於平緩路段，不再突然慢速拖行。
- **速度與笑點**：連續彎道會把椅子往外推，反打能減少擦撞；中央只保留兩個靠邊路障。龍泡泡使用有長度上限的角度彈簧拖繩，可獨立撞上路邊標誌／護欄，翻一圈、壓扁並冒星星，莊不會因此停車。飛行增加上下甩動與七組半透明空中警示框，碰撞加重為兩圈翻滾及更大的星星；警示框會傾倒消失。結算分開列地面／空中碰撞。全程維持賽道後方追拍，接管不切到人物前面，左右不反轉；鏡頭不隨跟班甩動無限拉遠。
- 這是原創二創短劇，獎品先保留神祕獎品，尚未加入對手 AI。暫停凍結劇情、施法與碰撞動畫，重來重播全部段落；祀線與原竹筏維持各自規則。
- `RideEngine` 管獨立駕駛規則，複用 `RaftEngine` 的固定步長與拖繩；原竹筏規則保留。`rideConfig` 集中路線／參數／文案，`RideProps` 生成道具與外型，`RideStage` 管場景與固定特效池，`RideGame` 管 UI。仍是唯一 Canvas／Renderer／render loop，DPR 上限 1.5、無新依賴或後處理。靜態模型按材質合併，煙霧 40、星星 8、拖痕 40 個實例重複使用，不會越玩越多。

莊線的時間／速度與短台詞集中在 `ZhuangRaceStory.js`，路線／碰撞物放在 `rideConfig.js`；切換角色會釋放原路線自有資源再建立對應路線，人物 GLB 與唯一 Renderer 保留。沿用煙霧／星星特效池，沒有新增依賴或渲染循環。自動測試包含 30／60／120 Hz 完整流程一致、可操作的開場／飛行、速度差、獨立碰撞與防重複、反打方向的實際效果、追尾視角左右與手機構圖，以及原骨架恢復。

這版驗證坐姿、甩尾與沙雕畫面；未製作正式帝江號資產、完整服裝物理或自由三軸飛行。實體 iPhone Safari 的幀率與手感仍待真機驗證。

## 清波寨竹筏－試作

[直接試玩竹筏](https://oloid666.github.io/endfield-si-viewer/#raft)，或遊戲區 → **清波寨竹筏－試作**。祀站在竹筏上，後方拖著近似「小聰明」的黑白幾何簡模；不是官方召喚物模型。青綠水面、竹林、碼頭、水車、屋頂及霧景均為原創簡化場景。

- 竹筏隨水道自動前進；按住左右或 A／D、方向鍵轉向，按住煞車或空白鍵減速並收近拖行距離，支援轉向與煞車同時觸控。
- 一段 255 公尺水道，順利行進約 45 秒；避開木樁、收集 7 個綠色墨印。撞岸／木樁會減速、濺水並吐槽，先不設沉船失敗，讓玩家試拖行甩尾手感。到岸顯示用時、墨印及碰撞次數，可重玩。
- 小聰明會延遲轉彎、左右晃動、拍手、浮沉；拖繩有長度上限。鏡頭同時照顧竹筏與跟班，直橫式自動調整。
- 暫停、切到背景或失去視窗焦點會停住進度、拖繩及水面動畫；支援繼續、重新出發、離開。返回角色展示時還原角色容器、骨骼、相機及場景背景。
- `raftConfig` 管路線設定，`RaftEngine` 使用固定步長的簡單彈簧拖行，`RaftStage` 管程序場景與原有祀模型，`RaftGame` 管手機輸入及狀態。沿用唯一 Canvas／Renderer／render loop，竹林等重複物件使用 InstancedMesh，無新依賴、即時陰影、反射或流體模擬。

這版先測操作與笑點，未加入龍泡泡／莊方宜竹筏、多人模式或正式清波寨美術。實體 iPhone Safari 幀率、熱負載及觸控手感仍待真機確認。

## 查勤爬塔試作：管理員，你人呢？

舊版可直接開啟 [爬塔原型](https://oloid666.github.io/endfield-si-viewer/#climb)。這是原創同人小關卡：管理員偷溜來找祀，回程電梯停機，祀必須搭息壤階梯趕到接駁口；佩利卡催回船，莊方宜中途來電查勤。

- 祀的既有 GLB 直接作為操作角色，附簡化移動、推拉、跨上一格的程序姿勢。固定斜前方鏡頭追蹤；使用側向單排 2.5D 關卡，尚不是四方向完整 3D 爬塔。
- ←／→ 或 A／D 移動，遇一格高台自動攀爬。「搬箱」／空白鍵切換推拉模式，關閉後才能踩上亮框方塊；↶／Z 退一步，幾何與位置復原，時間不倒退。
- 前段教學不計時；通過第一面高牆、接完來電後啟動 80 秒回船倒數與上升廢液。兩處高牆都需要搬動息壤搭路。
- 橘色破損息壤踩過 2.8 秒崩塌。泡泡龍目前是明確標示的原創搜尋代替物，固定左右巡查；方塊能遮住視線，被發現量累積滿會失敗。沒有引入官方泡泡龍模型。
- 莊方宜有兩個回覆選項與不同吐槽；讀取通訊、暫停及切到背景時凍結倒數、搜尋與崩解。勝敗都可重新開始，離場恢復原有模型展示或節奏遊戲。
- `climbConfig` 集中關卡／時間設定；`ClimbEngine` 管整數格規則、撤回及狀態；`ClimbStage` 重用場景與人物並釋放自有材質／幾何；`ClimbGame` 管手機按鍵、通訊與 UI。仍只用一個 Canvas／渲染循環，未新增依賴。

原型先驗證推拉、搜尋與查勤是否有趣；正式攀爬動畫、更多關卡、自由轉向、官方敵人模型、配音及正式美術尚未製作。息壤崩解、廢液設施與人物關係是本作二創規則。實體 iPhone Safari 效能仍待驗證。

## 遊戲選單與進階關卡

[遊戲選單](https://oloid666.github.io/endfield-si-viewer/#hub) 現在有四個同層入口：**甩蔥**（`#game`）、**爬塔－測試中**（`#escape`）、**清波寨竹筏－試作**（`#raft`）及 **迷你帝江號／辦公椅－試作**（`#ride`）。角色上方的「遊戲區」開啟此選單；各遊戲的返回按鈕也回到選單，不再把爬塔入口塞進甩蔥的開始面板。舊 `#climb` 網址仍保留，未放進主要索引。

爬塔原四關保留為教學／入門，第一關給 150 秒。另有七個進階測試（目前共 11 關），透過頂端「選關」下拉選單選擇；每關顯示星級，可隨時使用 **重來本關**。重來會保留選中的關卡，還原人物、箱子、門、材料、回收額度、倒數、通訊及暫停狀態；「退一步」還原上一步幾何與材料，不倒退時間。

| 關卡 | 難度 | 要思考的機制 |
| --- | --- | --- |
| ⑤ 別推下去 | ★★★ | 先繞到箱子另一側；把唯一階梯推入低槽會形成真正死路，需撤回或重來 |
| ⑥ 借位開門 | ★★★ | 息壤箱壓住綠色壓力板才開閘門，不能把箱子一路推走；單箱也無法翻越關閉的高門 |
| ⑦ 雙重查勤 | ★★★ | 兩段不同相位的噴流；紫光時不能爬入，必須在安全高度分段等待，後面再接短時回縮平台 |
| ⑧ 三塊不夠？ | ★★★★ | 五個缺口、三塊材料、僅兩次回收；規劃帶走哪塊，浪費材料／額度可讓後段卡住 |
| ⑨ 地下先通電 | ★★★★ | 地下留電箱開門，折返左繩上樓，把指定貨箱送到收貨框；只有人到門口不算過關 |
| ⑩ 密件拿了，路封了 | ★★★★★ | 取件後封住上層原路，還要下右繩蓋章、走地下回起點；出發前必須先鋪好回程 |
| ⑪ 先卸貨，後搭橋 | ★★★★★ | 先把電箱推下井，再搭唯一且不能回收的橋，折返運梯箱過橋爬高牆；先蓋橋會形成死路 |

新三關使用不同的上下層地形與任務，非教學地圖換計時；不新增中途電話。箱子有「電／貨／梯／墊」標記，下方任務會顯示完成狀態。開局及暫停面板可展開 **查看全圖與箱子分工**；全圖直接讀取當前格子，黃點是你、綠框是出口、虛框是收貨位。物品、封路機關及任務都能撤回或重來。可用 `?level=warehouse#escape`、`?level=vault#escape`、`?level=unload#escape` 直接選中新關；未知代號回第一關。

建造關多一個 **轉身／F**，不用移動也能回收身後材料；限額關會顯示剩餘回收次數。遊戲中會明確提醒已知低槽死路，重來不要求重新整理頁面。解法只放在測試 fixtures，不放進難關提示。

甩蔥的可選音訊不再無限等待：若 Safari 的 `AudioContext.resume()` 一直未完成，450 ms 後用視覺時鐘開局並顯示無聲提示。這是對同類無反應情況的保護，尚未宣稱在使用者的實體 iPhone 重現原始問題；正常音訊開局仍保留。

## 呱嘎管理員：初版四種玩法

[直接試玩爬塔](https://oloid666.github.io/endfield-si-viewer/#escape)，或遊戲區 →「爬塔－測試中」。上方下拉選單可隨時選關；過關可直接下一關。原有祀爬塔、節奏甩蔥及兩個角色展示仍保留。

主控是本站原創的簡單企鵝，暫代呱嘎管理員，並非對既有二創造型的精確重現。故事是管理員原本去武陵找莊方宜，途中又溜去找祀；莊突然提早抵達，之後佩利卡又要送文件簽名。這些情節、侵蝕與方塊規則均為同人設計。

| 關卡 | 操作／機制 | 目標 |
| --- | --- | --- |
| ① 推箱爬塔 | 左右移動；開啟搬箱推拉，關閉後攀一格 | 兩處高牆需要先推息壤搭階梯，趕回武陵落腳處 |
| ② 侵蝕鋪路 | 把可搬息壤蓋到紫色侵蝕上 | 從箱子上安全通過；不能把安全箱推走再踩侵蝕 |
| ③ 繩索逃班 | 到繩旁按住 ↑／W；↓／S 可下繩 | 黃光預警、紫光噴發；躲開中段噴流，再過會縮回的息壤平台，到接駁口回帝江號 |
| ④ 息壤建造 | E 放置、R 回收、Q 平橋／階梯切換 | 七塊材料搭過兩段斷橋；只能回收自己放的方塊 |

四關皆可用 ←／→ 或 A／D 移動、Z 撤回；空白鍵切換搬箱。手機提供對應大按鈕。操作後才開始抵達／送件倒數，尚未操作時可先觀察；通訊有兩種回覆及不同補刀，選擇與閱讀期間暫停倒數、噴流及回縮。暫停／背景切換需手動繼續。撤回會還原方塊與材料，不倒退查勤時間。

`escapeConfig` 集中關卡地圖、規則與故事；`EscapeEngine` 延用 `ClimbEngine` 的格子碰撞、推拉及撤回，加入繩索、侵蝕、回縮與材料建造。`EscapeStage` 延用工業場景／鏡頭，透過 `GuaguaActor` 取代 GLB 主角；`EscapeGame` 管選關、按鍵與通訊。直接開 `#escape` 不下載人物 GLB；若從展示區進入則暫時隱藏原人物，返回時恢復。仍是一個 Canvas／渲染循環，沒有新增產品依賴。

這是側向 2.5D 小關卡，不含完整 3D 自由建造、存檔、隨機地圖、正式呱嘎／泡泡龍模型或配音。莊方宜用既有模型渲染頭像，來源與 CC BY 4.0 留在遊戲素材說明；佩利卡用文字通訊。實體 iPhone Safari 的觸控手感、熱負載與 FPS 尚待驗證。

## 本機啟動

需要 Node.js 22.12+（或 20.19+）。

```sh
npm install
npm run dev
npm run build
npm run preview
```

在終端顯示的網址開啟。iPhone 與開發電腦位於同一網路時，可用電腦區網 IP 加上 Vite 的連接埠測試；需允許防火牆連線。

## 模型上傳與替換

- 預設將合法模型放在 `public/models/si.glb`，重新啟動／重新建置即可。
- 缺少模型時仍會顯示介面、錯誤訊息及「上傳本機 GLB」。選檔只在當前頁面記憶體使用，不會上傳或永久儲存；重新整理後恢復預設模型。
- 建議 GLB 內嵌貼圖。一般 GLTF 與外部貼圖可部署到 `public/models/`，再修改 `src/config/characters.js` 中對應角色的 `path`，保留 `.bin` 與貼圖的相對路徑；本機選檔目前只接受 GLB。
- 不附 Draco、Meshopt、KTX2 解碼器。遇到這些壓縮格式需先合法轉出一般 GLB，或後續按需要加入解碼器。
- 模型比例、材質、貼圖與骨架保持匯入狀態；只平移外層容器，不自動旋轉模型的朝向。若模型朝向不同，可自行旋轉觀看。
- 手機載入能力仍取決於模型大小、三角形數與貼圖解析度；建議先使用低負載版本，再於真機量測。

## 手機下載與離線快取

首次開啟時，支援原生 gzip 解壓縮的瀏覽器優先下載無損壓縮版：原模型 8,148,092 bytes，壓縮約 5.48 MB，減少約 33%。Vite 自動生成 `models/si.glb.gz` 及模型 SHA-256 版本，不修改原 GLB、材質或骨架；更換原檔後重新 build 即可，不需手動更新雜湊。舊瀏覽器或壓縮檔失效會退回原 GLB。

預設模型驗證成功後存進此瀏覽器的 Cache Storage，之後改版或重新整理可直接讀取模型，避免重複下載。模型版本變更時自動換新；私人瀏覽、容量不足或儲存不支援時仍可正常下載。瀏覽器可能自行清除快取，因此不保證永久離線。

下載 15 秒未收到資料會中止並重試一次，每次總下載上限 120 秒。載入畫面直接顯示已下載 MB、進度、重新下載及本機 GLB 入口；不必等到失敗才找選單。本機選檔會取消先前請求，且不會存進持久快取或上傳到伺服器。

## 操作

單指／左鍵旋轉，雙指縮放與平移，滾輪縮放，右鍵平移。水平可完整旋轉，垂直角度略避開極點。重設視角恢復完整模型的正面取景；視窗尺寸或方向改變時重新取景。

## GitHub Pages

1. 將此目錄的內容推送至 GitHub Repository 的 `main` 分支（若使用其他分支，調整 Workflow）。不需將 `dist` 或 `node_modules` 推上去。
2. Repository → Settings → Pages → Build and deployment → Source 選擇 **GitHub Actions**。
3. Push 或在 Actions 手動執行 **Deploy GitHub Pages**。
4. Workflow 以 `npm ci` 安裝並 build，從 `configure-pages` 自動取得 base path，再部署 `dist`。完成後從 deployment URL 開啟。
5. 模型必須與程式碼一同部署到 `public/models/si.glb`。留意 GitHub 單檔與 Pages 容量限制；大型模型不應直接提交。

預設 Vite base 為 `./`，支援本機與子目錄預覽；Workflow 會依 Pages 設定覆寫。模型 URL 使用 `import.meta.env.BASE_URL`。手動測試指定子路徑：

```sh
VITE_BASE_PATH=/endfield-si-viewer/ npm run build
VITE_BASE_PATH=/endfield-si-viewer/ npm run preview
```

沒有前端路由，於 Pages 根入口 `/REPOSITORY/` 重新整理即可；沒有宣告任意深層網址路由。本專案 Repository 為 https://github.com/Oloid666/endfield-si-viewer ，公開網站預期網址為 https://oloid666.github.io/endfield-si-viewer/ ，部署狀態可至 Actions 查看。

## 現行互動與角色動作

底部 ☰ 選單分四個獨立收合區：表情與眼神、原創角色動作、視角、其他。面板只在內部捲動；上傳、待機暫停及第二層模型署名位於「其他」。

### 三個動作

- **釘宮祀萌**：10 秒，叉腰、別頭偷看、被抓包、跺腳及延遲回彈，再偷看一次。
- **源祀技藝**：15.6 秒，變出毛筆，在空中畫四筆蔥畫，立體化交到手上，搭配兩個完整八拍舞步和三根伴舞蔥；最後一根慢半拍。沒有音樂。
- **蔥末地**：巨大蔥畫到一半長出水墨四肢，對看 1.5 秒，抓住祀反甩。10 秒時停住，跳出通訊選擇，沒有倒數也不會自動選擇：
  - **小蔥，我馬上來幫你！**：真的救援，跳過加碼，角色嘴硬道謝後回待機。
  - **別急，我給蔥續個八拍。**：恢復假結束停頓，再跳出「危機合約：禁止停手」，四圈大風車、水墨龍捲風，最後落款蓋章。演出本身 21.8 秒，不含玩家等待時間。

成功開始動作後自動收合面板；演出與復原完成後恢復原本展開狀態及捲動位置。途中手動開關面板會覆蓋自動恢復。收合時的「■ 停止」可中止；通訊選擇時可按 Escape 取消。鏡頭可由玩家拖曳接管自動運鏡。

### 表情與眼神

三個表情為 **原來是管理員／磁小軌／協議裡沒有這個吧！**。強度 0–200%，0% 不出文字；四區為 1–50%、51–100%、101–150%、151–200%，各有兩句 A／B 文案獨立輪替。拖動即時改表情，放手才觸發台詞。舊 0–200% 曲線已壓縮到 0–50%，51% 後加入另設計的誇張端點、漫畫符號與 UI 補刀。

高強度依序玩「廢料鑑定不予回收」「申請當管理員的管理員卻被駁回」「查無協議，系統當場更新」三個梗。每次只有一句主台詞及一張系統卡，不疊加多張；角色動作優先，中止表情字幕及攝影反應。

眼神可選看鏡頭、看點擊位置、自然待機、不追蹤。點擊模式只接受短暫單指輕點，拖曳、長按或雙指仍交給 OrbitControls。眼睛比頭部先反應，角度受限；越過背後角度接縫時保持同一側回頭，避免突然甩頭。

### 攝影互動

- **人呢？給我全身**：回完整正面取景。
- **靠近點**：臉部近看，人物小幅後仰，雙腳維持著地。
- **轉過去**：鏡頭沿半圈繞到另一側，不直線穿過人物；預設「看鏡頭」時眼睛先追、頭部再跟，身體不整個轉向。
- **合乎周禮 → 合乎舟禮 → 給我飯盒 → 吃飽了**：腿腳環繞、鞋靴放大環繞、鞋靴特寫環繞、回全身。手動拖曳中止環繞但保留檔位。

實際臉部取景停穩約 4 秒，會說「……看夠了？」；移開取消，每次取景只觸發一次。攝影互動讀取真實鏡頭與頭部距離，不只依按鈕名稱判斷；正式動作期間讓位。

### 模組與效能

`viewerConfig` 匯入 `interactionConfig`，集中管理四區文案、UI 時序與攝影參數。`ViewerDialogue` 管表情／攝影台詞，`PhotographyController` 管靠近及停留；`IdleController` 統一寫入骨骼並管理演出、選擇及救援狀態。

`BrushDrawing` 管世界座標筆畫與毛筆，`ReverseLeekController` 只移動 actor wrapper，不更動原骨架結構；`InkStage` 重用八筆墨痕、六片龍捲風弧帶與六個飛散墨點，無逐幀新增粒子。蔥共用生成的筆觸貼圖與表情圖集，模型替換及停止時正確清理。

所有演出仍只有一個 render loop、DPR 上限 1.5，沒有新增產品依賴、後處理、布料或流體物理。遊戲風 UI、文案與程序動作是本站原創改編，不是官方技能、動畫、聲優音檔或 MMD 資料。原 GLB 材質、貼圖及骨架結構保持不變。

後續可在同一骨架加入 Blender 動畫片段，再以 AnimationMixer 播放並保留眼神層。錄影模式、音樂、MMD 匯入及真機效能優化尚未實作。
