# 讓祀的動作更自然：研究與改進方案

研究日期：2026-10-19。以下現況描述以改進前版本為準。

執行進度：已實作程序動畫的自然站姿、分部位曲線、眼神先行、動機式眨眼、平滑取消與時間修正；第二輪已加入叉腰／腳部解析式 IK、少量手指握持與水墨蔥道具；Blender 動畫片段及頭髮次級動作仍未實作。部署結果請見 TESTING.md。

## 現況與原因

現有模型有骨架，但沒有內建動畫或 morph targets。現行動作是執行時疊加骨骼旋轉與位移，屬於動作原型，尚未達到角色表演品質。

- `IdleController.applyBody()` 讓腰、肩、手臂、手腕、膝蓋共用同一個 bodyAmount，部位同步啟停，看起來像擺姿勢。
- 所有通道使用相同 smoothstep 區間插值，缺少不同部位的加速、延遲、超越與回收。
- 高冷動作的身體參數在正規化時間 0.30–0.62 相同：5.2 秒 × 0.32 = 1.664 秒。害羞在 0.34–0.54 身體參數相同，約 1.16 秒。頭眼或呼吸可能仍動，但主要肢體停住。
- 動作收尾回到原模型展示姿勢，而非自然站姿。加大角度並不能解決這些節奏問題。
- 面部目前主要靠眉、眼皮與嘴角骨骼位移；沒有現成表情資產，能達到的細膩程度需要逐一驗證。
- 渲染循環把 delta 限制為 0.05 秒。持續低於 20fps 時，依 delta 累積的動作會比實際時間慢；這是程式風險，尚非 iPhone 實測瓶頸。

## 優先順序

1. **自然基礎站姿**：手臂放鬆、左右不對稱、手指微彎、重心偏一側。動作回到這個姿勢；呼吸作用於胸肩，避免全身規律搖擺。
2. **獨立部位曲線**：眼睛先選定目標，頭跟上，胸腰與肩稍後，手腕最後到位。加入預備動作與少量越過目標後的回收；大幅度保留，穿模不列為阻擋條件。
3. **重心與手部軌跡**：手走弧線，彎肘與翻腕分階段；髖、膝、腳配合，站立腳不要因上身扭轉而明顯滑動。
4. **有動機的表情**：轉頭或轉移注意力時眨眼；偷看先只移眼睛，再決定是否轉頭。眉、眼皮、嘴角不必同步達到最大值。停頓中保留微小的呼吸或視線反應，避免固定頻率亂晃。
5. **最後加次級動作**：頭髮、衣袖或飾物在身體停止後稍晚收住。先處理主要表演，再選少量骨骼；暫不加入完整布料物理或昂貴後處理。

## 兩個動作的表演設計

以下是待調整的設計節奏，不是已驗證的動畫。

| 動作 | 表演順序 |
| --- | --- |
| 1 高冷嫌棄、別過頭 | 先瞥你 → 眉壓低、微抬下巴 → 重心偏開、胸腰帶頭轉走 → 單手抬起擋一下、手腕最後翻開 → 側眼確認你還在 → 放下手，保留偏開的站姿再接回待機 |
| 2 嘴硬害羞、偷看你 | 先對視 → 短促眨眼、縮肩後仰 → 身體轉開、雙手前後錯開地抬到臉旁 → 眼睛先偷看，頭稍後轉回 → 被發現似的迅速移開視線 → 手逐步放下，回到自然待機 |

同一動作中加入快慢對比：快速反應、較慢遮掩、短暫猶豫。避免整段都用同一種平滑速度。兩個手臂不要鏡像同步。

## 實作路線

短期可以改造現有程序動畫：把單一 bodyAmount 拆成少數具名部位曲線，加入自然站姿、注意力狀態與過渡。先做「害羞偷看」一支的前後比較，不同時增加更多按鈕。

較長期推薦混合方式：在 Blender 使用這個模型原有骨架製作全身關鍵影格，離線處理手腳約束並烘焙成 glTF 相容動畫；網頁以 Three.js AnimationMixer 播放、AnimationAction 交叉淡化。眼神和眨眼保持程序控制，但必須明確分配骨骼控制權，避免與動畫片段互相覆寫。原始模型保留，動畫資產另存並維持來源標示。

AnimationMixer 解決播放與混合，不會自動把差的關鍵影格變自然。MMD/VMD 或通用動捕需要骨架映射、座標與比例校正，不能當作即插即用方案；目前不需要付費 API 或新框架。

## 驗收方法與限制

- 同鏡位錄製修改前後影片，分別看全身與臉部，正常速度與半速檢查。截圖只能驗證姿勢，不能判斷動作節奏。
- 檢查部位是否錯開啟停、手是否走弧線、腳有無滑動、結束是否自然銜接，而非只確認骨骼有位移。
- 測試 30/60fps 的動作時長一致、背景恢復不跳動、暫停及模型替換可正確收尾。
- 實機 iPhone Safari 測試旋轉時的動作流暢度與持續執行表現；暫以穩定 30fps 作為最低目標，尚未實測達成。
- 本次完成程式檢查與資料研究；沒有新增動畫、沒有更動線上版本，也沒有宣稱表演品質已改善。
